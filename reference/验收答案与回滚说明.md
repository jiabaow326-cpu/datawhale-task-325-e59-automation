## 二、错误清单的预演应当如何结束

从包根目录执行：

```powershell
python scripts/safe_batch.py --source-dir materials/source --manifest materials/manifests/处理清单_v2_待核验.csv --output-dir results/blocked-demo
```

应显示 `BLOCKED`、`目标文件名重复` 和 `找不到来源文件`，进程返回 2，且 `results/blocked-demo` 不被创建。若现象不同，停止并审查脚本/路径，不要加 `--apply`。

## 三、已核准演练清单的预期结果

用 `materials/manifests/演练已核准清单.csv`，计划为 3 个唯一来源分别复制为 3 个唯一目标名；源记录共 6 行，汇总表也有 6 个门店/品项组合：

| 门店 | 品项 | 总数量 | 总金额（虚构元） |
|---|---:|---:|---:|
| 白沙门店 | 咖啡豆 | 2 | 48 |
| 白沙门店 | 纸杯 | 1 | 7 |
| 松岚门店 | 咖啡豆 | 3 | 72 |
| 松岚门店 | 红茶 | 5 | 50 |
| 海棠门店 | 咖啡豆 | 4 | 96 |
| 海棠门店 | 纸杯 | 2 | 14 |

预演命令：

```powershell
python scripts/safe_batch.py --source-dir materials/source --manifest materials/manifests/演练已核准清单.csv --output-dir results/demo-run-001
```

预演不产生任何文件。人工逐行核对计划后，再加 `--apply`；目标目录必须事先不存在。运行产物：

- `copied/`：按目标名复制的三份源文件
- `summary.csv`：按门店、品项汇总的数量/金额
- `copy_manifest.csv`：源与输出文件的 SHA-256
- `run_record.json`：时间、路径与条数记录

复制源文件前脚本会先核对整份清单、所有输入 CSV 字段和值；一旦任一项不通过，就不创建输出目录。应用模式也只在全新目录写副本。`shutil.copy2` 会尝试保留可复制的元数据，但官方文档说明文件系统权限/附加流等部分元数据可能无法复制，不能把哈希一致误解成完整保留所有元数据。

## 四、回滚演练

脚本不含自动删除或撤销命令。若结果不合格：

1. 停止继续使用该输出。
2. 保留 `run_record.json`、清单与日志供检查。
3. 把整次 `results/demo-run-001` 移到同一练习区下的 `quarantine/`，或按组织批准的隔离方式处理；保留来源目录不变。
4. 确认原因并修复练习副本/核准清单，另选一个不存在的新输出目录，重新预演。

PowerShell 隔离示例（仅限此包内练习目录，先检查目标不存在）：

```powershell
New-Item -ItemType Directory -Path quarantine -ErrorAction Stop
Move-Item -LiteralPath results/demo-run-001 -Destination quarantine/demo-run-001
```

不要用回滚来清理正式资料。任何正式数据处理、恢复或删除都按组织授权流程交由有权人员决定。
